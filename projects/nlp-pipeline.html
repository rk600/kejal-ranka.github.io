AI / ML

Voice of Customer NLP Platform

Production AI pipeline • 18,000+ records/day • Self-improving system

Problem

Account managers across a major e-commerce marketplace record 18,000+ customer anecdotes annually. These contain critical signal: what programs customers care about, what blocks adoption, and how sentiment is shifting. But it all sits as unstructured free text — no one can systematically identify which levers drive positive outcomes, which blockers are most prevalent, or how trends evolve over time without manually reading thousands of entries.

Solution

I designed and built an automated AI enrichment pipeline that classifies each anecdote into structured dimensions using LLM inference, augmented with a knowledge base and few-shot learning from validated corrections.

Each record receives:

  • Category Labels — which programs were discussed (15 canonical categories)
  • Trends — what the customer said about each category (66 predefined + discovered)
  • Sentiment — Positive, Negative, or Neutral per category
  • Blockers — why the customer is hesitant (10 categories)
  • Summary — 1-2 sentence distillation

Architecture

ETL Job (SQL, ~4 min) → S3 (deduplicated parquet, 19K rows) → Lambda Trigger (dedup check + 6hr cooldown) → SageMaker Processing Job (25 concurrent threads, ~60 min) ├── Parse tags → canonical categories ├── Retrieve Knowledge Base context (35 entries) ├── Embed text (1024-dim vectors) ├── Find top-3 similar gold examples (cosine similarity) ├── Build 6-layer prompt → LLM inference └── Post-process (normalize, match taxonomy, threshold) → Enriched output (35 columns) → Real-time Dashboard

Key Design Decisions

Multi-Layer Prompt Architecture

Each inference call includes 6 layers of context ordered by specificity: stream identifier → knowledge base context → category taxonomy → few-shot examples → blocker categories → actual text + output schema. This ensures the model has domain expertise, classification guidance, corrective examples, and structured output format before seeing the input.

Self-Improving RAG System

A gold dataset of validated examples is embedded with 1024-dim vectors. At runtime, each record is compared via cosine similarity with boosting (+0.1 for same stream, +0.15 for same category). High-confidence outputs (≥0.95) are auto-harvested back into the gold set — growing it from 10 to 222 examples organically.

Accuracy progression: 10 gold examples → ~72% accuracy → 222 examples → ~80% accuracy → Target: 2,000 examples → ~92% (fine-tuning)

Knowledge Base Design

35 curated entries covering program definitions, category distinctions, common misclassification warnings, and blocker disambiguation. Distilled from 3 source documents. Prevents the model from confusing programs that sound similar but serve different purposes.

Impact

  • Product leadership can now identify top customer pain points without manual review of thousands of entries
  • Sentiment distribution revealed: 37% Negative, 33% Positive, 30% Neutral — with top blockers being Process Complexity, Trust, and Policy concerns

Tech Stack

  • Compute: AWS SageMaker (Processing Jobs), Lambda
  • AI/ML: Claude (Bedrock), Titan Embeddings (1024-dim), cosine similarity, few-shot RAG
  • Storage: S3 (parquet), DynamoDB (feedback loop)
  • Orchestration: Event-driven (S3 PUT → Lambda → SageMaker)
  • Serving: Real-time dashboard consuming enriched parquet
