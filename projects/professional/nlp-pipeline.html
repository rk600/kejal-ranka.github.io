A Pipeline That Teaches Itself

How I turned 18,000 unreadable text records into a self-improving classification system — and got invited to present it at a European leadership summit.

← Back to portfolio

🎯 Situation

Account managers across a major e-commerce marketplace record 18,000+ customer anecdotes per year across two programs. Each entry contains critical business signal: what programs customers care about, what blocks their growth, whether sentiment is improving.

But it's all free text. Messy. Inconsistent. No one reads 18,000 entries. Product managers had no systematic way to extract insights — they relied on manually skimming recent entries.

The question leadership asked: "What do our customers actually think about our programs — and how is that changing over time?"

Nobody could answer it. Not with data.

⚡ Task

Build a system that:

  • Classifies every anecdote into structured dimensions (program category, sentiment, trend, adoption blocker)
  • Runs daily, automatically, with zero human intervention
  • Serves results to product leadership via a real-time dashboard
  • Gets more accurate over time — without a dedicated labeling team
The constraint that made it hard
Zero labeled training data existed. No taxonomy had been defined. 38 different tag variants mapped to 15 canonical categories — with no documentation. And the accuracy bar was high: inaccurate classifications would erode stakeholder trust quickly.

🔧 Action

Architecture: Event-Driven, Self-Improving

SERVE Enriched parquet (35 cols) → Real-time dashboard PMs see: trends × sentiment × category × time

The Breakthrough: 6-Layer Prompting

Zero-shot accuracy was ~70%. Not terrible, but not trustworthy. I discovered that layering context in a specific order dramatically improved quality:

  • Layer 1: Stream identifier (which program family)
  • Layer 2: Knowledge base — what each program does, common mistakes to avoid (35 curated entries from 3 source documents)
  • Layer 3: Taxonomy — predefined labels to choose from (66 trends)
  • Layer 4: Few-shot examples — 3 most similar validated entries from gold set (cosine similarity + stream/category boosting)
  • Layer 5: Blocker categories (10 predefined adoption barriers)
  • Layer 6: The actual text + JSON output schema

Each layer addresses a specific failure mode I observed. The knowledge base alone gave a bigger accuracy lift than any prompt engineering — because the model simply didn't know what the programs were.

Self-Improving Without Human Labelers

The system grows its own training data:

Gold Set SizeAccuracyHow
10~72%Manual seed (I labeled 10 examples)

The key insight: you don't need humans to label everything. You need humans to label a few, then let high-confidence outputs teach the system the rest.

🧠 What I'd Do Differently

  • Start with the knowledge base, not the model. I spent time tuning prompts before realizing the model simply didn't know what the programs were. The KB gave a bigger lift than any prompt trick.
  • Build the eval harness on Day 1. I couldn't measure improvements reliably until I built a proper eval harness. Should have been the first thing I built.
  • Human-in-the-loop is a people problem, not a tech problem. The feedback infrastructure exists end-to-end (DynamoDB, dashboard thumbs up/down). But PMs don't have bandwidth to review. Auto-harvest sidesteps this for now.
